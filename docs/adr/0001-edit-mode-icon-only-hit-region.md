# ADR 0001: 編集モードの項目押下判定をアイコン矩形に限定する

- Status: Accepted
- Date: 2026-08-24

## Context

通常モードのトップレベル項目は、起動しやすさのためアイコン画像だけでなく、その下のラベル帯もクリック領域に含めている。編集モードでも同じ hit-test を共有していたため、アプリ名を押すと項目ドラッグが始まり、項目間の狭い隙間から編集モードを終了しにくかった。

フォルダ内の子項目は既にアイコン矩形だけを `FolderChild` として登録し、ラベル帯を `FolderPanel` として扱っている。トップレベルとフォルダ内で、編集モード中の操作契約を揃える必要がある。

## Decision

通常モードの起動判定はラベル帯込みのまま維持する。編集モードの押下判定には専用の `layout::edit_mode::press_hit_at` を使用し、実在する項目のアイコン／タイル矩形だけを `GridHit::App` とする。

同じ項目のラベル帯は `GridHit::EmptyInFrame` として分類し、既存の空き領域クリックと同じ経路で編集モードを終了する。トップレベルのアプリとフォルダタイルの双方にこの規則を適用する。

フォルダ内は既存の z-order と hit map を維持する。子アイコン矩形は `FolderChild`、子ラベルは背面の `FolderPanel` に解決されるため、編集モード中のラベルクリックは folder page press/release 経路から編集モードを終了する。

## Consequences

- 通常モードでは従来どおりアプリ名をクリックして起動できる。
- 編集モードでは、ドラッグと削除バッジの対象はアイコン画像範囲に限定される。
- アプリ名の領域が編集モード終了用の空き領域として使えるため、項目間隔を広げずに終了操作を行いやすくなる。
- 起動用、編集押下用、編集ドロップ用の hit-test は目的別に分かれる。今後ジオメトリを変更する場合は、3つの契約を個別に確認する必要がある。
- `qa/edit_mode_label_exit.json` と純粋ジオメトリテストで、トップレベルとフォルダ内の両方を回帰確認する。
