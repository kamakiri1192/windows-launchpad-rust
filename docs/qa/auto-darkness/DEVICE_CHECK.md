# 自動darkness 判定方式: 実機チェックガイド (issue #186 / PR #198)

検証harnessの結果は `results.md` と `contact_sheet.png` を参照。この文書は
**実機(Windows)で最後に1回流すだけで全部比較できる**手順。

## 前提

- `cargo build --release` 済みバイナリ
- 設定 → **Darkness** → 「自動的にdarknessを調整」ON
- 設定 → **Debug** → 「Liquid Glass」トグルON(画面に `Dynamic darkness: 0.xxx`
  のHUDが出る。この値が現在の判定方式の出力)

## 切り替えられるもの(すべてセッション限定・非永続化、再起動でリセット)

| 操作 | 場所 | 効果 |
|---|---|---|
| 判定方式: Current / Coverage tuned / Contrast | Darkness | 判定式の切り替え |
| 局所判定: モーダル | Darkness | フォルダ/コンテキストメニュー/設定パネル直下だけの局所判定 |
| Dynamic darkness最大値 | Darkness | darknessの上限(既存スライダー) |
| 判定: Full rate / Adaptive / Fixed 8 Hz | Darkness | 更新レート(既存。診断用) |

## 一巡チェックの手順(10分)

1. **基線**: 判定方式=Current で、白い背景(ブラウザの空白ページ等)を背面に開く。
   HUDの値と見た目を確認 → **Coverage tuned** に切り替えて差を見る(浅い白背景で
   弱い暗さが入るようになる) → **Contrast** に切り替えて差を見る(入るか/強すぎるか)
2. **半々背景**: 画面の半分が白くなるようにウィンドウを置く。Current は暗くならない
   (全体平均で希釈)、Contrast は暗くなることを確認
3. **彩度の高い明るい背景**(黄色系ページ): Current/Coverage tuned は反応なし、
   Contrast は暗くなる
4. **暗い背景**: 3方式とも darkness 0 のまま過暗化しないことを確認
5. **局所判定**: 白い背景の一部にフォルダ/コンテキストメニュー/設定パネルを開き、
   「局所判定: モーダル」をON/OFF。ON時はモーダル直下の明るさに追従する
   (HUDはグリッド側の値なので、モーダルの見た目で判断)
6. **上限の確認**: 真っ白背景で文字が読みにくいままの場合、Dynamic darkness最大値を
   0.16→0.30 程度まで上げると読みやすくなるか(harnessの知見: 明背景での読みやすさは
   方式ではなくこの上限に律速されている)

## 判断材料(実機で見るべきポイント)

- Coverage tuned が現行より「全体的に」良さそうか(浅い白背景に弱い暗さが乗るか)
- Contrast は明背景で強く効きすぎないか(ライトグレー背景で一気に暗くなる設計上の
  特徴=オール・オア・ナッシング。許容かどうか)
- 局所判定はモーダルの追従感が良いか(グローバルとの見た目の一貫性が崩れないか)

## 注意

- 方式切替時はGPU状態をリセットするため、切替直後に0.18〜0.30sの遷移が入り直す
- 判定は最長8Hz(Adaptive時)なので、背景を変えてから1秒以内にHUDが追従すれば正常
