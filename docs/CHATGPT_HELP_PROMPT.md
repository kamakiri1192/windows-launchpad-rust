# ChatGPTヘルプの質問文

## 目的

「ChatGPTにアプリの使い方を質問する」の最初の回答を、機能の網羅的な調査レポートではなく、一般利用者が用途を理解し、代表的な操作を一つ完了できるガイドにする。

従来は「アプリを使いこなす」ことを目標に、全主要機能の用途・操作・具体例、ショートカット、ジェスチャー、隠れた機能、推奨設定、互換性、OS連携、複数画像を同時に要求していた。「読みやすく」と付け加えるだけでは、必須項目の多さや説明の重複は解消しない。

新しい回答の順序は次のとおり。

1. 最初の1〜2文で、何に使うアプリなのかを身近な例で示す。
2. 「できること」は目的と効果を2〜3件。単機能アプリなら無理に件数を増やさない。
3. 「まず○○してみる」で代表的な操作を一つ説明する。通常3〜5手順を目安に、画面・操作対象・動作を具体化し、最後に完了の目印を示す。保存や書き出しが必要なら省略しない。
4. 初回操作に役立つ注意点・コツだけを最大2件添える。不要ならこの節を省略する。

本文は日本語600〜1,000字、英語250〜400語程度を目安とし、正しく操作するのに必要な説明を優先する。文字数や手順数に合わせて複数操作を曖昧な1行に詰め込まない。詳しい応用は追加質問で扱い、最後の提案も具体的な質問を一つまでにする。

## 正確性と画像

公式ドキュメント・サポート・リリースノート・各OSの公式ストアを優先する調査方針は維持する。名前だけでなく開発元・識別子・OSを照合し、ファイルバージョンだけを根拠に製品を特定しない。

アプリを確実に特定できない場合は通常のガイドを埋めず、確認できたことと不明点を短く伝え、識別に必要な情報を一つ尋ねる。確認済みのシステム部品・補助ツール・コマンドラインツールは、その役割に合う説明にする。たとえば「Global Configuration」という名前だけからWindows設定アプリと決めつけたり、架空のGUI操作を作ったりしない。

画像は、操作対象を見つける助けになる確認済みスクリーンショットを最大1枚。別製品の画像やロゴ、宣伝画像、画像がないことを説明するだけの章は不要。画像なしでも手順が成立することを優先する。検索できない環境では確認済みと装わず、その制約を一度だけ伝える。

## 実装範囲

- `src/app/chatgpt_help_prompt.md`：回答の目的・構成・調査条件。`include_str!`でコンパイル時に埋め込むため、実行時のファイル配布・読み込みは増えない。
- `src/app/command.rs`：既存のメタデータ整形とURL生成を維持し、ロケールを明示して検証できる純粋なヘルパーを追加。
- 外部APIの追加、データベース変更、画面変更、起動方法変更は行わない。ローカルのショートカット／実行ファイルパスを質問文へ追加しない。

テンプレートの指示は英語で保持するが、回答本文・見出しの言語は従来どおりOSロケールから指定する。不明なロケールは英語へフォールバックする既存方針を維持する。取得できた未対応言語タグの扱いも既存実装から変更しない。

## 検証とその限界

`command.rs`のChatGPT関連テストは13件。タスク優先の指示、識別不能時の分岐、画像の任意化、日本語・英語等のロケール、未取得メタデータ、空のアプリ名、改行・引用符の整形、ローカルパス非包含、予約文字・日本語を含むURLの完全な往復を対象とする。テストが確認するのは生成する質問文の契約であり、ChatGPTが必ず従うという保証ではない。

```sh
cargo fmt --all -- --check
cargo test --locked chatgpt_
cargo clippy --all-targets --all-features --locked -- -D warnings
```

今回の作業環境にはRustツールチェーンがなく、上記Rustコマンドはローカルでは未実行。テンプレートに対する独立したPythonの静的チェックでは、Windows/macOS × 日本語/英語 × 6種類のメタデータ、計24パターンの埋め込み、欠損値、省略、URLの往復を確認した。対象例の最大URL長は6,633バイトで、既存の8,192バイトのプロジェクト予算内。ただし任意長メタデータ全般に対する上限保証や、全ブラウザーの動作保証ではない。
