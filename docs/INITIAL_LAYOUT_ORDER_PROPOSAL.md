# 初期配置の優先順とWindowsツール分割

- 状態: ユーザー承認済み・実装済み（配置仕様v3、カタログv5）。既存配置は自動変更しない。
- 2026-09-25のユーザー要望と、この端末の検出結果を基にする。
- 初回／明示的な設定リセットに限り、従来の名前順へ用途の優先度を加える。

## 目的

最初に見える場所から、日常の入口と主要な作業アプリへすぐアクセスできるようにする。
設定、エクスプローラー、電卓、Microsoft Store、Chrome、Edge、Discord、OBS、Adobeを前方へ配置する。
管理・診断・サポート・機器設定の項目が名前順だけで先頭を占めることを避ける。

起動履歴は使わない。ここでいう優先度は製品が用意する初期値であり、ユーザーの実測使用頻度ではない。
保存後の並びはユーザーが所有し、起動回数・アプリ更新・言語変更で自動的に変えない。AI機能も使用しない。

## 所属と順番を分ける

既存のアプリ識別と重複整理 → フォルダ所属の決定 → 初期配置の優先順 → 保存、の順に処理する。
「単独表示」と「後ろへ置く」は別の判断。「フォルダ化」と「後ろへ置く」も別の判断として扱う。
Adobeはフォルダのまま前方へ、設定と電卓は直接前方へ、PC管理はフォルダにまとめて後方へ置けるようにする。

## 初期優先順

| 優先帯 | 役割 | この端末での例 |
| --- | --- | --- |
| 0 | 日常の入口 | エクスプローラー、Chrome、Edge、Discord、Microsoft Store、設定、電卓 |
| 1 | 作業を始めるアプリ・製品群 | Adobe Creative Cloud、OBS Studio、Blender、Unreal Engine、Visual Studio Code、ChatGPT、文書スイート、Unity、JetBrains、Live2D Cubism、Maxon |
| 2 | 一般アプリ・未分類アプリ | その他の既知製品、Steam、VR Games、VLC、リモートデスクトップなど。未分類のアプリもここで名前順 |
| 3 | 補助・設定・管理 | Windows Dev tools、Visual Studioツール、Git付属コマンド群、機器設定フォルダ、Game Bar、PC管理、明示識別した補助起動モード |

Windowsアクセサリは帯1の後半に置く。アクセシビリティは一般帯に置き、使用頻度が低いと決めつけて管理帯に落とさない。
VRツールは用途のある独立アプリ群として一般帯に置く。各フォルダの所属製品を増やしても優先度はフォルダ単位で安定させる。

帯0と帯1の先頭には明示的な順序を持たせる。同じ帯・同じ優先値は従来の名前順＋安定IDで決める。
一般帯では名前順を保つ。未分類だからという理由だけで最終ページへ追いやらない。

上表は製品が用意する初期値であり、全アプリの人気順を推定するものではない。実際に存在する項目だけ配置する。
複数ブラウザは各々直接配置する。同じ製品の版違いを大量に先頭へ並べないよう、製品ごとの先頭候補は代表1件とし、残りは一般帯へ回す。既存フォルダ内の複数版はそのまま保つ。
代表を選ぶ場合は明示的な安定版のバージョン情報を用い、Preview/Betaを表示名の曖昧な推測で優先しない。識別できない場合は安定ID順とする。

## Windows関連の整理

| 置き場所 | 含めるもの |
| --- | --- |
| 直接表示・前方 | 設定、エクスプローラー、電卓、Microsoft Store |
| Windowsアクセサリ | メモ帳、Snipping Tool、ペイント、クロック、サウンドレコーダー、付箋などの日常の補助アプリ |
| PC管理 | コンピューターの管理、イベントビューアー、サービス、タスクスケジューラ、レジストリエディタ、ディスク管理・診断、コントロールパネル、Windowsセキュリティ、バックアップ、問い合わせ、フィードバックHubなど |

PC管理という名前にすることで、Windows純正に加えてNVIDIA Control Panelや明示識別したGlobal Configuration等の機器・コーデック設定も無理なく収められる。
管理・診断・機器設定をPC管理にまとめる。
既存のOMEN・Razerなどは製品ごとのフォルダを維持して後方へ配置する。入れ子は作らない。

タスクマネージャー、ターミナル、PowerShell、コマンドプロンプト、ファイル名を指定して実行は日常の操作用としてWindowsアクセサリへまとめる。Visual Studio専用の開発者シェルは既存フォルダを維持する。

フォルダ内も用途が分かる順にする。Windowsアクセサリではメモ帳・切り取りなどを先頭へ、PC管理ではWindowsセキュリティ・コントロールパネル・バックアップを先頭へ置き、詳細な管理・サポート機能を後ろへ並べる。その他の製品フォルダ内は既存の名前順を維持する。

Game Barは通常のアプリとして一般帯より後ろへ置く。PC管理へ無理に混ぜない。
VLCの通常起動は一般帯、設定リセットやスキン起動は補助帯とし、異なる操作を重複アプリとして消さない。

## この端末での先頭の例

1. エクスプローラー、Google Chrome、Microsoft Edge、Discord、Microsoft Store、設定、電卓。
2. Adobe Creative Cloud、OBS Studio、Blender、Unreal Engine、Visual Studio Code、ChatGPT、Windowsアクセサリ。
3. 続いて制作・文書用の製品群、一般アプリ。その後に開発付属ツール・機器設定・PC管理。

これは保存する論理順の例。行数や列数は画面サイズに従う。
1ページ目を特別な固定領域にはせず、優先順の先頭から通常のグリッドへ流し込む。欠けているアプリの空き枠やダミーは作らない。
狭い画面では優先アプリでも次ページへ続き、アプリが少ない環境では管理フォルダまで1ページに収まることがある。
「管理アプリを絶対に2ページ目以降へ置く」保証は設けず、空白によるページ送りは導入しない。

## 識別と既存実装への追加

- Windowsストア・設定・電卓・セキュリティなどは確認したAUMID／Shellの識別情報を使う。
- コンピューターの管理など、現在外に残っている.msc項目はSystemRoot内の限定パスおよび起動引数を照合して分類する。
- explorer.exe、rundll32.exe、mmc.exeなどの共有ホストはexe名だけで分類しない。特定フォルダへのショートカットや別の管理機能を、標準エクスプローラーなどと混同しない。
- Global Configurationは表示名ではなく、実機で確認したDLL・エントリポイントなどの起動情報を確認して登録する。
- ブラウザ、Discord、OBSなども、既存のカタログ方針に従い製品の識別根拠を登録する。
- フォルダにはpreset_idを使って順位を付ける。保存後のフォルダ名を手がかりに再分類しない。
- フォルダ未成立の場合でも、Adobeの制作アプリなどは自身の優先度で前へ置く。逆に管理アプリが1個だけでフォルダ未成立なら、単独のまま後方へ置く。
- 初期生成処理にだけ優先順を追加する。共有の名前順比較・検索順・ユーザーの手動整列は変更しない。
- macOSは今の並びを維持する。Windows固有のルールを流用しない。

## 適用・保存・取り消し

初回と設定リセットに適用する。既存配置の自動書き換え、追加入力、ダイアログは導入しない。
初回スキャンが不完全でも取得済みのアプリを整理する。後から見つかったアプリはトップレベル末尾へ追加し、フォルダや優先順を再生成しない。
並びだけ変わった場合も「初期整理を取り消す」の対象にする。
初期配置のバージョンを記録し、ユーザーが移動した後は優先ルールを再適用しない。新しいアプリは従来どおり末尾へ追加する。

## 検証項目

- 指定した日常アプリとAdobe・OBSが管理項目より前に並ぶ。
- 1製品・フォルダ成立なし・異なる版が複数ある場合も優先順が働く。
- Store・.msc・Shell項目がWindowsフォルダへ入り、同じホストを使う別アプリを誤分類しない。
- フォルダ化前後で全IDが一度ずつ残る。検索とSteam非表示設定も維持する。
- スキャン順・言語・アイコン到着順で役割の順位が変わらない。同順位の名前順だけが表示言語に対応する。
- 小さい画面、初期フォルダが一つもない環境、取り消し、再起動、手動編集後、設定リセットを確認する。
